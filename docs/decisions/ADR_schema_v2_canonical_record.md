# ADR: Canonical Schema v2 Canonical Record

**Status:** Accepted (T10)  
**Date:** 2026-07-10  
**Schema version:** `2.0.0`  
**Migration version:** `v1_to_v2-1.0.0`

## Context

Schema v1.0.0 (`src/ambiguity_manager/schema/*`) is frozen. T01 legacy enums conflict with the updated global contract. T10 introduces schema v2 without rerunning T00–T09 converters or mutating v1 artefacts.

## Decision

### Implementation style

- Standard-library **dataclasses**, **StrEnum**, explicit validators, and JSONL helpers under `src/ambiguity_manager/schema/v2/`.
- **No Pydantic** or other new validation dependency.
- A deterministic **JSON Schema export** at `src/ambiguity_manager/schema/v2/schema.json`, constructed by `json_schema.py` from the same Python enums and structural definitions. The Python implementation remains authoritative; the JSON file is a derived interchange artefact, not a second source of truth.

### Machine publication vs human reports

`scripts/migrate_schema_v2.py --publish` atomically publishes **machine migration outputs only**:

```text
data/interim/schema_v2/**
data/processed/schema_v2/weak_pool/**
outputs/manifests/schema_v2_migration_manifest.json
outputs/manifests/schema_v2_weak_pool_manifest.json
outputs/metrics/schema_v2_migration_summary.json
```

Human-facing reports are **tracked static repository deliverables**, maintained alongside T10 code and not regenerated by the migration CLI:

```text
docs/decisions/ADR_schema_v2_canonical_record.md
docs/reports/schema_v2_migration_report.md
docs/reports/ticket_T10_completion_report.md
```

The migration manifest contract must not claim that `--publish` writes these markdown files.

### Versioning

- v1 constant remains `1.0.0` and is unchanged.
- v2 constant is `2.0.0`.
- Migrated records set `migrated_from_schema_version: "1.0.0"` and `migration_version: "v1_to_v2-1.0.0"`.

### Canonical enums (authoritative for unfinished work)

```text
risk_level: none | low | medium | high | unknown
capability_status: capable | conditional | incapable | unknown
```

Legacy v1 → v2 mappings (deterministic, logged in migration accounting):

```text
unknown_until_clarified → unknown
partially_capable → conditional
```

- Reject `uncertain` and all other unsupported values.
- Do not coerce malformed values to `unknown`.

### Record classes and nullability

| Class | Purpose in T10 |
|---|---|
| `source_converted` | Migrated converter output |
| `adjudicated_gold` | Reserved; same nullability rules |
| `prediction` | Schema support only; **not generated in T10** |

- **Gold/source:** `risk_level`, `capability_status`, and other unavailable labels may remain `null` when metric-ineligible.
- **Prediction:** when `label_eligibility.<field>` is true, the corresponding prediction field must be non-null and use an allowed enum value.
- `TODO_VERIFY` retains v1 behaviour: all `label_eligibility` booleans must be false.

### CPC representation

Structured `cpc` object with thirteen slots:

```text
action, actor, object, object_attributes, destination, spatial_relation,
quantity, time, recipient, tool, conditions, constraints, negation
```

Each slot:

```json
{"value": "<string|null>", "status": "filled|missing|unknown|not_applicable"}
```

Default for unmigrated slots: `status=unknown`, `value=null`.

### Evidence-backed legacy slot mapping table

Observed v1 slot keys across six datasets (T10 inspection):

| Dataset | Observed slot keys | CPC mapping | Unmapped handling |
|---|---|---|---|
| ambik | _(none — empty `{}`)_ | — | — |
| codraw_icr_v2 | _(none)_ | — | — |
| clara | _(none)_ | — | — |
| clariq | _(none)_ | — | — |
| vague | `subject`, `action`, `object` | `subject→actor`, `action→action`, `object→object` | Evidence: `vague.py::parse_solution_triplet`, `docs/mapping/vague_mapping.md` |
| indirect_requests | 37 unique dynamic `slot_description` keys (744 filled instances) | **No CPC mapping** — keys are schema-domain labels, not proven CPC slot names | Preserve full `{key: value}` under `v1_legacy.slots`; count keys in migration accounting |

No heuristic, keyword, fuzzy, or LLM mapping is permitted.

### Unmappable legacy preservation

- Unmapped slot keys/values remain in `v1_legacy.slots` (complete copy of v1 `slots`).
- `missing_slots` → `unresolved_slots`; original list preserved in `v1_legacy.missing_slots`.
- `gold_clarification_question` → `clarification_question`; original in `v1_legacy.gold_clarification_question`.
- `resolved_interpretation` stays in `v1_legacy`; **not** copied to `selected_interpretation`.
- v1-only fields without v2 equivalents are counted under `unmappable_fields` reasons (`not_present_in_v1:*`).

### Candidate and selected interpretations

- v1 `{text, confidence?, safety_status?}` → v2 candidate frame with deterministic `frame_id={id}:candidate:{index}`, empty CPC, preserved text/confidence/safety.
- `selected_interpretation` requires non-empty `supporting_evidence` and a matching candidate `frame_id`.
- Migrated records keep `selected_interpretation=null`.

### Context-sampling uncertainty

Optional structured field (`score`, `variant_count`, `agreement`). Migrated records: all null; no T18 calibration in T10.

### Metric eligibility

- Field name remains **`label_eligibility`** (not renamed).
- Values preserved exactly from v1 unless a new v2-only field requires a documented eligibility extension (none in T10).

### ID preservation

- Logical `id` unchanged across migration.
- No schema version suffix on IDs.
- IDs are not recomputed on source-file reordering.

### Weak pool rebuild

- v2 primary and auxiliary pools are **rebuilt from migrated v2 interim** outputs using T09 ordering and physical separation policies.
- v1 pool files remain read-only reconciliation evidence.

### Atomic publication

1. Hash protected v1 inputs (6 interim + 3 pool files).
2. Build complete output tree in a temporary staging directory.
3. Validate counts, IDs, pool↔interim equality, and protected hashes.
4. Refuse publication if any final **machine** destination exists.
5. `os.replace` each staged file to final path via `_atomic_publish`; on any failure, unlink any destinations published in that attempt and raise `SchemaV2MigrationError`.
6. Human markdown reports are outside this atomic set (see **Machine publication vs human reports** above).
7. Machine manifests use sorted-key JSON without timestamps, git SHA, or absolute paths.

## Consequences

- All unfinished tickets must target schema v2.
- v1 modules, converter outputs, and v1 weak pools remain immutable evidence.
- Prediction record validation is available for future tickets without T10 generating predictions.
